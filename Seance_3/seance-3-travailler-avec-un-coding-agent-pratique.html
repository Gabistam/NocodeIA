Prompt de départ

Contexte : je développe [CinéList / GameBacklog / CampusHub], un projet Next.js (App Router, TypeScript, Tailwind) décrit dans PROJECT.md. Le design system est dans DESIGN.md et les règles de travail dans AGENTS.md.

Rôle : agis comme un développeur front-end Next.js rigoureux qui respecte strictement le design system et modifie le moins de fichiers possible.

Objectif : réaliser la tâche décrite dans tache.md (une page statique avec des données fictives).

Actions attendues :
1. Lis PROJECT.md, DESIGN.md, AGENTS.md et tache.md.
2. Propose un plan numéroté (fichiers créés ou modifiés, rôle de chacun) et attends ma validation avant d'écrire du code.
3. Après validation, exécute uniquement le plan.
4. Lance npm run lint puis npm run build et montre-moi les sorties.

Contraintes :
- Aucune nouvelle dépendance, aucun fichier supprimé, aucune réécriture complète d'un fichier existant.
- Couleurs, typographies et rayons issus de DESIGN.md uniquement.
- Composants réutilisables dans components/, données fictives dans lib/.
- Pas de base de données ni d'authentification à ce stade.

Exemple de réponse attendue pour le plan :
1. lib/films.ts : tableau typé de 6 films fictifs
2. components/FilmCard.tsx : carte d'un film
3. app/ma-liste/page.tsx : page qui affiche la grille de cartes

Termine par la liste des fichiers modifiés et la vérification de chaque critère de fin.

# Tâche agent — Page statique « Ma liste » (CinéList)

## Objectif
Créer la page /ma-liste qui affiche la watchlist de l'utilisateur sous forme de grille de cartes, à partir de 6 films et séries fictifs, en respectant strictement DESIGN.md.

## Contexte (fichiers à lire)
- PROJECT.md
- DESIGN.md
- AGENTS.md
- app/layout.tsx
- app/globals.css

## Contraintes
- Next.js App Router, TypeScript strict (aucun type any)
- Tailwind uniquement, avec les couleurs, rayons et typographies de DESIGN.md
- Données fictives typées dans lib/films.ts (titre, type film ou série, année, statut à voir ou vu, affiche en couleur de fond)
- Composant réutilisable components/FilmCard.tsx
- Composant serveur par défaut, pas de "use client" sans nécessité
- Grille : 1 colonne en mobile, 2 en tablette, 3 en desktop
- État vide prévu : message « Votre liste est vide » si le tableau est vide

## Étapes attendues
1. Lire les fichiers de contexte
2. Proposer un plan numéroté (fichiers et rôle de chacun), puis attendre ma validation
3. Créer lib/films.ts, puis components/FilmCard.tsx, puis app/ma-liste/page.tsx
4. Ajouter un lien « Ma liste » dans le header existant sans modifier le reste du layout
5. Lancer npm run lint puis npm run build et coller les sorties
6. Lister les fichiers modifiés et vérifier chaque critère de fin

## Critères de fin
- npm run lint et npm run build passent sans erreur
- /ma-liste affiche 6 cartes avec titre, type, année et badge de statut
- Couleurs et rayons conformes à DESIGN.md, aucune valeur hexadécimale en dur
- Affichage lisible en largeur mobile
- L'état vide s'affiche si le tableau de films est vide
- git diff ne montre que les fichiers prévus dans le plan

## Interdits
- Aucune nouvelle dépendance dans package.json
- Aucun fichier supprimé ni réécrit entièrement
- Pas de Supabase, pas d'authentification, pas d'appel réseau
- Pas de modification de PROJECT.md, DESIGN.md ou AGENTS.md
- Pas de git push ni de commande git destructrice
