Prompt de départ

Contexte : je livre le MVP de mon projet [CinéList / GameBacklog / CampusHub], une application Next.js (App Router, TypeScript) avec Supabase (Postgres, Auth, RLS), versionnée sur GitHub et déployée sur Vercel. Lis PROJECT.md, AGENTS.md, AI-LOG.md, .env.example et package.json avant de commencer.

Rôle : agis comme un développeur senior chargé de la mise en production et de la documentation d'un projet étudiant.

Objectif / Action :
1. Audite le repository : fichiers inutiles, .gitignore, présence de secrets dans le code ou l'historique, .env.example complet.
2. Liste les points à vérifier avant le déploiement Vercel et la configuration Supabase de production (Site URL, Redirect URLs, migrations, RLS).
3. Rédige un README.md avec : pitch, fonctionnalités livrées, stack, installation, variables d'environnement (noms et rôle uniquement), URL de démo, comptes de test, limites connues.

Contraintes :
- Ne cite que des fonctionnalités et des commandes qui existent réellement dans le code et le package.json.
- N'écris jamais la valeur d'une clé ; SUPABASE_SERVICE_ROLE_KEY reste côté serveur.
- Signale explicitement ce que tu ne peux pas vérifier au lieu de l'inventer.
- Propose d'abord ton plan, attends ma validation, puis modifie les fichiers.

Exemple de ton attendu pour une fonctionnalité : « Watchlist personnelle : ajout, statut vu / à voir, note sur 5, protégée par RLS. »

Exemple corrigé — CinéList
# CinéList

> La watchlist des étudiants cinéphiles : gardez la trace des films et séries à voir, notez ce que vous avez vu et partagez vos avis.

**Démo :** https://cinelist.vercel.app

## Fonctionnalités

- Inscription, connexion et déconnexion (Supabase Auth, email + mot de passe)
- Watchlist personnelle : ajout, modification, suppression d'un film ou d'une série
- Statut « à voir » / « vu » et note sur 5
- Avis écrits sur un titre, visibles par les autres utilisateurs
- Favoris
- Recherche par titre et filtre par genre et par statut
- Dashboard personnel : nombre de titres vus, à voir, note moyenne
- Interface responsive (mobile, tablette, desktop) conforme à DESIGN.md
- Données isolées par utilisateur grâce à la Row Level Security

## Stack

- Next.js (App Router) + TypeScript
- Supabase : Postgres, Auth, Row Level Security
- Tailwind CSS
- Git / GitHub, déploiement Vercel
- Agent de code : Claude Code (contexte : PROJECT.md, DESIGN.md, AGENTS.md)

## Modèle de données

- `profiles` : profil lié à `auth.users`
- `titles` : films et séries (titre, type, genre, année)
- `watchlist_items` : relation utilisateur / titre (statut, note)
- `reviews` : avis d'un utilisateur sur un titre
- `favorites` : titres favoris d'un utilisateur

Le schéma est versionné dans `supabase/migrations/`.

## Installation

```bash
git clone https://github.com/votre-compte/cinelist.git
cd cinelist
npm install
cp .env.example .env.local   # puis renseigner les valeurs
npm run dev
```

L'application est disponible sur http://localhost:3000.

Pour appliquer le schéma sur votre propre projet Supabase :

```bash
supabase link --project-ref <votre-ref>
supabase db push
```

## Variables d'environnement

| Variable | Rôle | Exposition |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | URL du projet Supabase | Publique |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Clé publique, protégée par la RLS | Publique |
| `SUPABASE_SERVICE_ROLE_KEY` | Opérations d'administration côté serveur | Serveur uniquement |

Aucune valeur n'est versionnée : voir `.env.example`.

## Scripts

- `npm run dev` : serveur de développement
- `npm run build` : build de production
- `npm run lint` : analyse ESLint

## Limites connues

- La recherche ne gère pas encore les accents (« Amelie » ne trouve pas « Amélie ») : piste, recherche insensible aux accents côté Postgres.
- Pas encore de suppression de compte en libre-service : prévue dans la prochaine itération.
- Les affiches ne sont pas encore récupérées automatiquement (bonus envisagé : API TMDB via une route serveur).

## Méthode IA

Le projet a été construit avec un agent de code piloté par des fichiers de contexte (`PROJECT.md`, `DESIGN.md`, `AGENTS.md`). Les décisions importantes, propositions refusées et vérifications sont consignées dans [`AI-LOG.md`](./AI-LOG.md).
